## 第一部分 · 项目说明（技术侧）

## 一、项目概述

**三角占领**是一套用于"萌新杯"音游比赛的实时计分控制系统。双方阵营（防守方/进攻方）通过完成歌曲挑战占领 7 层三角形地图上的格子，在 25 分钟限时内争夺最高分；进攻方还可通过连通能源激活 L1 源头触发"顶端直胜"瞬间逆转。

| 项目 | 说明 |
|------|------|
| 定位 | 单机本地运行（`python app/main/main.py`），浏览器访问 |
| 语言 | Python 3.10+（无数据库、无构建步骤） |
| 后端 | FastAPI + Uvicorn（REST + WebSocket） |
| 前端 | 原生 HTML/CSS/JS，无框架 |
| 通信 | WebSocket 状态实时推送 |

## 三、已确认的规则定论（实现时以此为准）

> 以下为两份原始文档交叉比对后经确认的规则。**更新链顺序固定，顺序不可换。**

### 3.1 更新链（B3）

任何占领变更后，固定执行：

```
occupy / cancel_occupy
        │
        ▼
update_activation()      # 重算激活状态（激活决定包围判定，必须最先执行）
        │
        ▼
check_encirclement()     # 每局限一次：成立则永久标记被围地块并退化非守护者地块
        │
        ▼
recalc_scores()          # 重算双方分数（含 L1 实时分、能源加成）
        │
        ▼
check_top_victory()      # 检查顶端直胜
        │
        ▼
push_state_update()      # WebSocket 推送
```

### 3.2 L1 源头特殊规则（A1/A2/A3）

| 规则 | 定论 |
|------|------|
| 归属判定 | 提交 `score` + `tp` 双参数，**优先比 score，同分比 tp**，高者占据 |
| 得分豁免激活 | 进攻方占领 L1 即得分，无需激活 |
| 豁免包围 | L1 完全豁免包围：**不进入包围集合**（无包围样式/无 `[包围]` 标注/不受退化影响），双方可反复争夺直至游戏结束 |
| 顶端直胜需激活 | 进攻方占 L1 **且** L1 `activated == true` 才触发直胜 |

> ⚠️ 关键矛盾点：L1 得分不需要激活，但触发顶端直胜必须激活。进攻方占 L1 立即加分，但只有 L1 通过能源连通被激活时才赢得游戏。

### 3.3 包围判定（B1/B2）

**判定本质**：判断是否存在一个区域，使得该区域内的格子**不可能被进攻方以任何方式激活**。

从 **L1（id=0）** 出发 BFS：

| 格子类型 | BFS 行为 |
|---------|---------|
| 防守方占领格 | **墙体**，不可通过 |
| 进攻方**已激活**格 | **失败触发点**，触及即包围失败 |
| 能源格 | **失败触发点**，触及即包围失败 |
| 未占领格 / 进攻方未激活格 | 可通过 |

- BFS 穷尽未触及失败点 → **包围成立**；包围范围 = visited 中非防守方、非能源格，**不含 L1（id=0，完全豁免包围）**
- **包围每局只触发一次**：触发后 `encircled_cells` **永久标记**（不再解除，也不可再次触发）
- 触发时，包围区内**非守护者占领的地块自动退化为未占领**（owner→None、activated=False，无残留分数）
- 退化后地块恢复正常可占领状态（双方均可占领），但**永久保留包围标记**（虚线边框 + 蓝点）
- 已移除 `reoccupy`：不再需要手动重占，退化由系统自动完成

### 3.4 能源加成上限（修正）

每格能源加成 = `min(energy_count - 1, 2)`，**上限 +2/格**：

| 连通块接触能源数 | 1 | 2 | 3 | ≥4 |
|----------------|---|---|---|---|
| 每格加成 | +0 | +1 | +2 | **+2（上限）** |

### 3.5 顶端直胜（修正）

进攻方占领并激活 L1 即**直接获胜**，防守方当前分数**保留不变**（不吞噬、不累加）。

> 说明：比赛积分涉及奖品兑换等场外因素，顶端直胜只决出胜负，不并入防守方积分。

### 3.6 占领不可变

除 L1（可反复争夺）外，任何格子被占领后**不可被覆盖、不可被改变归属**（包围退化是把非守护者地块自动清空为未占领，不是覆盖）。

### 3.7 包围触发效果

包围每局只触发一次：被围地块**永久标记**，其中**非守护者占领的地块自动退化为未占领**；退化后仍可被双方正常占领，但标记保留。

## 四、地图结构

7 层三角形网格，共 27 格（ID 从上到下、从左到右编号 0–26）：

```
            [0]               ← L1 (1格, 可反复争夺, 直胜节点)
          [1] [2]             ← L2 (2格)
        [3] [4] [5]           ← L3 (3格)
      [6] [7] [8] [9]         ← L4 (4格)
   [10] [11] [12] [13] [14]   ← L5 (5格)
 [15] [16] [17] [18] [19] [20] ← L6 (6格)
 [21] [22] [23] [24] [25] [26] ← 能源层 (6格, 不可占领)
```

| 层 | ID 范围 | 格数 | 说明 |
|----|---------|------|------|
| L1 | 0 | 1 | 可反复争夺，顶端直胜节点 |
| L2 | 1–2 | 2 | 可占领 |
| L3 | 3–5 | 3 | 可占领 |
| L4 | 6–9 | 4 | 可占领 |
| L5 | 10–14 | 5 | 可占领 |
| L6 | 15–20 | 6 | 可占领 |
| 能源 | 21–26 | 6 | **不可占领**，仅用于连通判定 |

**邻接规则**（实现为 27 格硬编码邻接表）：

| 边类型 | 目标 | 条件 |
|--------|------|------|
| 左儿子 | 下一层同 index | 非 L6 格 |
| 右儿子 | 下一层 index+1 | 非 L6 格 |
| 左兄弟 | 同层 index−1 | index > 0 |
| 右兄弟 | 同层 index+1 | index < 该层格数−1 |
| 左父 | 上一层同 index | 非 L1，且 index < 上层格数 |
| 右父 | 上一层 index−1 | 非 L1，且 index > 0 |

能源格仅与正上方的 L6 格邻接：21↔15, 22↔16, 23↔17, 24↔18, 25↔19, 26↔20。

### 5.1 Cell

```python
@dataclass
class Cell:
    id: int                    # 0–26
    layer: int                 # 1–7
    is_energy: bool            # 第 7 层为 True
    owner: str | None          # "defender" / "attacker" / None
    activated: bool            # 仅进攻方使用（连通能源为 True）

    difficulty_label: str      # "Glitch 15+" 展示用
```

## 六、核心算法

### 6.1 update_activation（激活判定）

一个进攻方格子被激活 ⟺ 存在一条路径从该格走到某能源格，路径上所有中间格均为进攻方占领。

```
function update_activation():
    所有非能源格 activated = false
    for e in [21..26]:                      # 6 个能源格
        for n in neighbors(e):
            if n.owner == "attacker" and not n.activated:
                BFS from n，仅经过 owner=="attacker" 的非能源格
                全部标记 activated = true
```

> L1 若被进攻方占领且连通能源，也会被标记 activated（用于直胜判定），但 L1 得分不依赖 activated。

### 6.2 check_encirclement（包围判定）

```
function check_encirclement():
    visited = {0}; queue = [0]              # 从 L1 出发
    while queue:
        cur = queue.pop(0)
        for nid in neighbors(cur):
            if nid in visited: continue
            nb = cells[nid]
            if nb.owner == "defender": continue        # 墙 → 跳过
            if nb.is_energy: return FAIL               # 触及能源 → 包围失败
            if nb.owner == "attacker" and nb.activated:
                return FAIL                            # 触及已激活 → 包围失败
            visited.add(nid); queue.append(nid)
    encircled = {id for id in visited
                 if cells[id].owner != "defender"
                 and not cells[id].is_energy}
    return SUCCESS, encircled
```

### 6.3 recalc_scores（计分）

```
function recalc_scores():
    def_score = 0; atk_score = 0

    # 防守方：占领即得分（含 L1）
    for cell in 非能源格:
        if cell.owner == "defender":
            def_score += cell.total_score

    # 进攻方：L1 无需激活即得分；其余格需激活
    for cell in 非能源格:
        if cell.owner != "attacker": continue
        if cell.id == 0:                  # L1 豁免激活
            atk_score += cell.total_score
            continue
        if not cell.activated: continue   # 未激活不计分

    # 进攻方能源加成（仅已激活格，L1 不参与）
    visited = set()
    for cell in 非能源格:
        if cell.owner=="attacker" and cell.activated and cell.id not in visited:
            block = BFS_attacker_block(cell.id)   # 仅含已激活进攻方格
            visited |= block
            energy_count = count_energy_contacts(block)
            bonus = min(energy_count - 1, 2) if energy_count >= 1 else 0
            for bid in block:
                cells[bid].energy_bonus = bonus
                atk_score += cells[bid].total_score + bonus
```

### 6.4 check_top_victory（顶端直胜）

```
function check_top_victory():
    l1 = cells[0]
    if l1.owner == "attacker" and l1.activated:
        game_over = True
        winner = "attacker"
        win_type = "top"
        # 直接获胜，防守方分数保留不变（不吞噬、不累加）
```

## 七、API 设计

### 7.1 REST

### 7.3 事件日志格式

事件日志（`/api/events/export` 导出 + 前端事件面板）采用统一格式：

```
[mm:ss] <队伍> 占领了L<层>第<N>个格子 的<歌名> <任务> (<得分>) [标注]
```

- **mm:ss**：真实游玩时间（与计时器一致，游戏开始后经过的分:秒）
- **队伍**：`守护者` / `掠夺者`
- **N**：层内格子编号，**从 1 开始**
- **歌名**：歌曲名；无歌曲库时回退为难度标签
- **得分**：单格总分（难度分 + 任务加分）
- **L1 占领**：含 `score` 与 `tp`（`(score=900000, tp=99.5)`）；tp 未填写时仅显示 `(score=900000)`

**标注规则**（`[ ]` 后缀，可叠加）：

| 场景 | 标注 |
|------|------|
| 防守方占领 | `[守卫]` |
| 进攻方已激活 | `[已激活]` |
| 进攻方未激活 | `[未激活]` |
| 已激活格所在连通块接触 ≥2 个能源 | 追加 `[能源+N]`（N=接触能源数） |
| 占领 L1 | `[占领L1]`（替代其他标注） |
| 格子处于包围区（永久标记） | 追加 `[包围]` |

**示例**：

```
[00:05] 守护者 占领了L6第1个格子 的Frozen Mirage 90w (15) [守卫]
[00:05] 掠夺者 占领了L6第2个格子 的Inferno Paradox 达成tp99.5以上 (16) [已激活]
[00:06] 掠夺者 占领了L6第3个格子 的Crystal Rapture 达成tp98以上 (14) [已激活][能源+2]
[00:06] 守护者 占领了L1源头 的Solar Burst L1源头 (固定+10) (score=900000, tp=99.5) [占领L1]
```

特殊事件（系统消息如初始化/包围成立/游戏结束）保持原文，时间同样为真实游玩时间。

## 八、任务随机生成器与歌曲库流水线

### 8.1 歌曲库 JSON 格式

```json
{
  "songs": [
    {"name": "Vindication", "type": "Glitch", "level": "15+"},
    {"name": "Chronostasis", "type": "Chaos", "level": "14"},
    {"name": "Iris", "type": "Hard", "level": "12+"}
  ]
}
```

- `type` 枚举：`Glitch` / `Chaos` / `Hard`
- `level`：含加号，支持 `16`、`16+` 等
- **≥23 首**（流水线抽取下限）、歌名唯一

### 8.2 level → diff_score 映射

> 得分只取决于等级数值，`type` 前缀（Chaos/Glitch/Hard）不影响；实现为 `song_lib.level_to_score` 正则提取数字。
> `config/rules.json` 的 `difficulty_score` 键为**存档参考**，实际判定走 `level_to_score`（两者键集不一致，勿直接读配置）。

| level | diff_score |
|-------|-----------|
| 15+ / 16 / 16+ / 17…（≥15+） | 15 |
| 15 | 10 |
| 14 / 14+ | 8 |
| 13 / 13+ | 6 |
| 12 / 12+ | 5 |
| 11 / 11+ | 4 |
| 9-10+ | 3 |
| ≤8 | 2 |

### 8.3 任务分布（按 `rules.json` 权重，16 项）

| 任务 | 权重 | task_bonus |
|------|------|-----------|
| 达成MM | 2 | +10 |
| 达成tp99.5以上 | 1 | +10 |
| 达成99.5w以上 | 1 | +10 |
| 达成tp99以上 | 2 | +8 |
| 达成97w以上 | 2 | +8 |
| 达成tp98以上 | 5 | +6 |
| 达成95w以上 | 5 | +6 |
| 达成tp97以上 | 8 | +4 |
| 达成93w以上 | 8 | +4 |
| 达成tp96以上 | 8 | +3 |
| 达成92w以上 | 8 | +3 |
| 达成tp95以上 | 6 | +1 |
| 达成91w以上 | 6 | +1 |
| 达成90w以上 | 6 | 0 |
| 达成FULL COMBO | 4 | +7 |
| 达成miss <= 1, bad <= 1, good <= 1 | 10 | +5 |

> 以上 16 项任务均进入随机池，MM 没有豁免逻辑；规则集中在 `app/config/rules.json`。

### 8.4 开局任务流水线（歌曲库模式）

```
POST /api/songs 导入歌曲库（≥23 首，歌名唯一）→ POST /api/init
① 随机抽 23 首（不重复）→ 每首配随机任务 → 按总得分排序
② 删最高 1 个 + 最低 1 个 → 21 格恰好填满
③ 随机抽模板 A/B/C → 按区域权重贪心匹配（top=1/mid=9/shallow=5/energy=6）
```

- L1（id=0）固定 `task_bonus=10`、`task_name="L1源头 (固定+10)"`

### 8.5 无歌曲库回退

`generate_tasks(seed)` 保留：按 8 档等概率随机生成难度标签 + 权重任务，保证一局仅一首 15+。仅用于无歌曲库场景的兼容验证，正式开局必须走歌曲库流水线。

## 九、棋盘模板（三模板）

> 为避免纯随机开局导致难度分布方差过大，预设若干套平衡模板，每局从模板池随机抽取一套。任务类型仍按权重随机生成。

区域划分（战略位置）：
- **top 封顶位**：L1（id 0）
- **mid 中腹**：L2+L3+L4（id 1-9）
- **shallow 浅层**：L5（id 10-14）
- **energy 能源接入**：L6（id 15-20）

| 模板 | top | mid | shallow | energy | 战术倾向 |
|------|-----|-----|---------|--------|---------|
| **A 稳守反攻** | 高 | 中 | 低 | 中 | 高分任务落封顶位，防守方占优 |
| **B 能源攻势** | 中 | 低 | 中 | 高 | 高分任务落能源位，进攻方占优 |
| **C 中腹对峙** | 中 | 高 | 中 | 低 | 高分任务落中腹，正面拉锯 |

**匹配算法**：权重值 high=3, medium=2, low=1；区域按 `(权重降序, 固定顺序: energy→mid→shallow→top)` 排序；任务按得分降序贪心放入"剩余空位>0 且排序最靠前"区域的随机格。效果：每局高分任务集中在模板指定战略区。

## 十三、游戏背景

由于"萌新杯"举办次数过多，主办方陷入了财政危机，再也没有奖品可以发出去了，导致活动热度不断下滑，再也没有人玩了qwq

"既然这样，那只能使出那一招了"

为了拯救"萌新杯"，同时秉持着让更多人来参与一场有趣的音游比赛的初心，决定派出采矿船，去到遥远的泰拉世界去开采至纯原石，作为活动补贴支撑萌新杯继续活下去！

由于派出的采矿船遭遇了宇宙射线的影响，导致了采矿舰队分成了两批，一批率先到达了目标行星，另一批遭遇了宇宙乱流，等到另一批采矿船到达目的地时，原先的舰队居然自立政权，居然是为了独吞至纯原石在宇宙贸易中的巨大利益！为了争夺至纯原石，两方舰队开展一场旷日持久的战争...

## 十四、阵营与目标

| 阵营 | 别名 | 颜色 | 定位 |
|------|------|------|------|
| **守护者** | 防守方 | 蓝色 | 先到一步，占据矿脉，稳扎稳打守卫领地 |
| **掠夺者** | 进攻方 | 红色 | 后发制人，连通能源激活矿脉，伺机直取源头 |

**胜利条件**（满足其一即胜）：
1. **顶端直胜**：进攻方占领 L1 源头且将其激活 → 立即获胜（防守方分数保留不变）
2. **计时结束**：25 分钟到，分数高者胜（同分则平局）

## 十五、占领规则

- 双方可在**任意未被占领的格子**上执行任务（完成歌曲挑战）。
- 每个队员同一时间只能占领一个格子（3 人团队）。
- 同队不可同时占领同一格；不同队伍可竞争同一格，先完成者占领。
- **占领不可变**：除 L1（可反复争夺）外，任何格子被占领后**不可被覆盖、不可被改变归属**（包围触发会退化非守护者地块为未占领）。挑战失败方只能转向其他格子。

### L1 源头（特殊）

- 游戏开始时指定一首歌曲，**可反复争夺**。
- 每次挑战提交 **分数（score）+ TP** 两个数值。
- **归属判定**：优先比 score，score 相同则比 tp，高者占据 L1。
- L1 不受普通占领机制限制，即使落入包围区仍可继续挑战。

### 任务形式

占领一格 = 游玩一首指定难度的歌曲，满足以下任一条件即算完成：

| 任务 | 额外加分 | 权重 | 说明 |
|------|---------|------|------|
| 达成MM | +10 | 2 | 单曲达成 MM 即完成任务 |
| 达成tp99.5以上 | +10 | 1 | TP 达到 99.5 |
| 达成99.5w以上 | +10 | 1 | 分数达到 99.5w |
| 达成tp99以上 | +8 | 2 | TP 达到 99 |
| 达成97w以上 | +8 | 2 | 分数达到 97w |
| 达成tp98以上 | +6 | 5 | TP 达到 98 |
| 达成95w以上 | +6 | 5 | 分数达到 95w |
| 达成tp97以上 | +4 | 8 | TP 达到 97 |
| 达成93w以上 | +4 | 8 | 分数达到 93w |
| 达成tp96以上 | +3 | 8 | TP 达到 96 |
| 达成92w以上 | +3 | 8 | 分数达到 92w |
| 达成tp95以上 | +1 | 6 | TP 达到 95 |
| 达成91w以上 | +1 | 6 | 分数达到 91w |
| 达成90w以上 | +0 | 6 | 分数达到 90w |
| 达成FULL COMBO | +7 | 4 | 全连击 |
| 达成miss <= 1, bad <= 1, good <= 1 | +5 | 10 | miss、bad、good 均不超过 1 |

> 注：达成 xx 分数视为分数**大于等于**指定分数。任务按 `app/config/rules.json` 的权重随机抽取，共 16 项任务。

## 十六、计分规则

### 防守方（守护者）

- **占领即得分**，无任何连通条件。
- 每个被占领的非能源格子贡献 `total_score = 难度分 + 任务加分`。

### 进攻方（掠夺者）

- **已激活**的格子：得 `total_score` 分。
- **未激活**的格子：**不得分**（仅占地，不贡献分数）。
- 激活判定见第六节。

### 能源加成（进攻方专属）

每个**已激活**格子额外获得能源加成：

| 连通块接触能源数 | 1 | 2 | 3 | ≥4 |
|----------------|---|---|---|---|
| 每格加成 | +0 | +1 | +2 | **+2（上限）** |

- **连通块** = 通过邻接边相互连接的一组进攻方已激活格子。
- **能源接触数** = 该连通块内任意格子邻接的不同能源格数量。
- 不同连通块各自独立计算。
- 加成上限为 **+2/格**（接触 3 个及以上能源时封顶）。

**示例**：一个 8 格连通块接触 4 个能源 → 每格 +2 → 额外 8×2 = 16 分加成。

## 十七、激活机制（进攻方核心）

一个进攻方占领的格子被**激活**，当且仅当：存在一条路径从该格走到某个能源格，路径上所有中间格子均为进攻方占领。

- 从所有能源格（21-26）出发，沿邻接边做 BFS，经过的所有进攻方占领格子标记为已激活。
- 已激活格才计分 + 享受能源加成。
- 已激活格在棋盘上显示金色方块标记 + 右上角 `(+x)` 加成。
- 未激活格半透明淡化，不贡献任何分数。
- 若连通路径被防守方切断（占领了路径上的关键格子），相关格子会立即变为未激活，停止计分。

## 十八、包围机制（防守方专属）

判断是否存在一个区域，使得该区域内的格子**不可能被进攻方以任何方式激活**。

从 **L1（顶端）** 出发执行 BFS：

| 格子类型 | BFS 行为 |
|---------|---------|
| 防守方占领格 | **墙体**，不可通过 |
| 进攻方**已激活**格 | **失败触发点**，触及即包围失败 |
| 能源格 | **失败触发点**，触及即包围失败 |
| 未占领格 / 进攻方未激活格 | 可通过 |

- BFS 穷尽所有可达区域后，**未触及**上述两种失败点 → **包围成立**。
- **包围每局只触发一次**（不可重复触发、不会解除）。
- 触发效果：
  - 被围地块（包围范围内所有非防守方、非能源格，**不含 L1**）被**永久标记**（蓝色虚线边框 + 左下角蓝点）。
  - 其中**非守护者占领的地块自动退化为未占领**（owner→None、已激活状态清除、分数即时重算）。
  - 退化后的地块恢复为普通未占领格，双方均可正常占领，但**标记永久保留**。
- L1 完全豁免：不进入包围范围、不受退化影响，双方可继续用 score/tp 反复争夺。
- 已移除原「包围区重占」（reoccupy）机制——退化由系统自动完成。

## 十九、胜利条件详解

### 顶端直胜（彩蛋）

**触发条件**：进攻方占领 L1 **且** L1 处于激活状态（连通到能源）。

**结果**：
- 进攻方**立即获胜**。
- 防守方当前分数**保留不变**（不吞噬、不累加）。
- 触发"谐律崩解"特效。

> 说明：比赛积分涉及奖品兑换等场外因素，顶端直胜只决出胜负，不并入防守方积分。

### 计时结束

25 分钟到，比较双方分数：分数高者胜，分数相同则平局。

## 二十四、策略建议

### 防守方（守护者）策略

| 策略 | 思路 | 适用场景 |
|------|------|---------|
| **性价比优先** | 抢低难度高分格（如 L6 的 90w 任务），分数效率最高 | 通用最优 |
| **封顶** | 占领 L2 切断进攻方通往 L1 的路径，阻止顶端直胜 | 对方明显冲顶时 |
| **切断连通** | 在进攻方连通路径上插入己方格，使其失去激活 | 对方能源路线成型时 |
| **触发包围** | 用己方格封闭一片区域，让区内进攻方格全部失效 | 对方集中一侧时 |

### 进攻方（掠夺者）策略

| 策略 | 思路 | 适用场景 |
|------|------|---------|
| **能源路线** | 优先占 L6 连通能源，再向上扩展连通块，吃能源加成 | 通用稳健 |
| **冲顶直胜** | 建立 L6→L5→...→L1 的完整连通路径，激活 L1 直接获胜 | 对方防守松散时 |
| **混合战术** | 先建 2 个能源基础，再尝试冲顶，被堵则转能源 | 灵活应对 |
| **占地压制** | 占领不连通的格子（不计分但占地），阻止防守方扩张 | 战术性封锁 |

### 关键提醒

- **能源加成是进攻方的核心优势**：一个接触 4 能源的连通块，每格多 +2 分，累积可观。
- **顶端直胜是终局手段**：一旦激活 L1，进攻方立即获胜，比赛直接结束。
- **包围是防守方的核武器**：一次成功的包围能让进攻方大片区域失效。
- **时间管理至关重要**：25 分钟限时，高难度格子耗时更长，需权衡分数效率。

## 二十五、常见问题

**Q：进攻方占领了格子但不计分？**
A：该格未激活（不连通能源）。需要建立从能源格到该格的进攻方占领路径。

**Q：为什么我的进攻方格突然变成未激活？**
A：连通路径被防守方切断了（防守方占领了路径上的关键格子）。

**Q：L1 被进攻方占领了但没触发直胜？**
A：直胜需要 L1 处于激活状态。仅占领不够，必须连通能源激活 L1。

**Q：包围触发后，被围的地块会怎样？**
A：被围地块被**永久标记**（蓝色虚线边框 + 左下角蓝点）；其中非守护者占领的地块会**自动退化为未占领**，双方之后都可以正常挑战这些格子，但标记保留。

**Q：包围能触发几次？**
A：**每局只触发一次**。触发后即使再形成包围区域也不会再次触发或清除标记。

**Q：为什么我点击对方已占领的格子没反应？**
A：占领不可变。除 L1（可反复争夺）外，格子被占领后不可被覆盖或改变归属。

**Q：分数相同怎么判？**
A：计时结束时分数相同判平局。L1 挑战时分数相同则比 TP。

## 二十六、术语表

| 术语 | 含义 |
|------|------|
| 激活 | 进攻方格子连通能源的状态，激活后才计分 |
| 连通块 | 进攻方已激活格子通过邻接边连成的区域 |
| 能源接触数 | 连通块邻接的不同能源格数量 |
| 包围 | 防守方封闭一片区域（每局一次）：被围地块永久标记，非守护者地块退化为未占领 |
| 顶端直胜 | 进攻方激活 L1 后立即获胜的彩蛋机制 |
| TP | 音游中的精度指标（Technical Point） |
| 达成MM | Million Master，单曲完美结算，达成即完成任务 |
| FC | Full Combo，全连击不断 |
