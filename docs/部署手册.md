# 萌新杯音游比赛平台 — 部署手册

> 目标环境：**国内轻量服务器**（腾讯云 / 阿里云香港轻量 2C2G 优先，**免备案**）。
> 观众主要在国内，**不使用 Cloudflare Pages**，采用单机单体部署（后端托管前端产物，单端口 8000 跑通全站）。

---

## 0. 部署前准备

### 0.1 服务器选购

| 项 | 建议 |
| --- | --- |
| 云厂商 | 腾讯云 / 阿里云 |
| 节点 | **香港轻量 2C2G 优先（免备案）**；若用大陆节点需 ICP 备案 |
| 配置 | 2 核 2G 起步，带宽按观众量选（轻量 3~5Mbps 够用） |
| 系统 | Ubuntu 22.04 / Debian 12（推荐）或 CentOS 7+ |
| 域名 | 可选。有域名可配 Caddy 自动 HTTPS；无域名可用 IP + HTTP |

### 0.2 备案提醒（重要）

- **大陆节点**：域名必须完成 **ICP 备案**，否则云厂商会拦截 80/443 端口，HTTPS 无法生效。
- **香港节点**：**免备案**，可直接绑定域名并启用 HTTPS。
- 若暂时无域名，可先用 `http://服务器IP:8000` 访问，后续再补域名 + Caddy。

### 0.3 默认密码警告（必须执行）

> ⚠️ **部署上线前必须修改默认密码！**

种子数据包含以下默认弱口令账号，公网暴露前**必须修改或删除**：

| 角色 | 账号 | 默认密码 |
| --- | --- | --- |
| 管理员 | `admin` | `admin123` |
| 裁判 | `referee` | `referee123` |
| 选手 | `player1` ~ `player8` | `player123` |

修改方式：登录后台 → 用户管理 → 重置密码；或删除这些种子账号后重新创建。

## 1. 密钥管理

### 1.1 生成 SECRET_KEY

```bash
python -c "import secrets; print(secrets.token_hex(32))"
```

把输出的一长串随机值作为 `SECRET_KEY`。**不要**使用默认值 `dev-secret-change-me`。

### 1.2 密钥存放

- **方案 A（Docker）**：写入 `deploy/docker-compose.yml` 的 `environment.SECRET_KEY`，或通过 `.env` 文件注入。
- **方案 B（systemd）**：写入 systemd unit 的 `Environment=` 或 `EnvironmentFile=`。

> 切勿把真实密钥提交到 git。`.env`、`*.db` 已在 `.gitignore` 中。

## 2. 方案 A：Docker Compose（推荐）

### 2.1 安装 Docker

```bash
# Ubuntu / Debian
curl -fsSL https://get.docker.com | sh
sudo systemctl enable --now docker

# 验证
docker --version
docker compose version
```

### 2.2 克隆仓库

```bash
git clone https://github.com/Pixel-fish-123/competition_web.git
cd competition_web
```

### 2.3 配置 SECRET_KEY

编辑 `deploy/docker-compose.yml`，把 `SECRET_KEY` 替换为 1.1 生成的随机值：

```yaml
environment:
  SECRET_KEY: "你的随机密钥"
```

### 2.4 构建并启动

```bash
docker compose -f deploy/docker-compose.yml up -d --build
```

首次构建会拉取 `node:20-alpine` 与 `python:3.14-slim` 镜像并编译前端，耗时几分钟。

### 2.5 验证

```bash
# 查看容器状态
docker compose -f deploy/docker-compose.yml ps

# 查看日志
docker compose -f deploy/docker-compose.yml logs -f app

# 本地验证首页（应返回 HTML）
curl -s http://127.0.0.1:8000/ | head
```

### 2.6 数据持久化

SQLite 数据库文件位于容器内 `/app/data/competition.db`，通过卷挂载持久化到宿主机 `deploy/data/`。备份时直接对宿主机 `deploy/data/competition.db` 操作即可（见第 4 节）。

## 3. 方案 B：systemd 裸跑（无 Docker）

### 3.1 安装 Python 3.14 与 Node 20

```bash
# Ubuntu / Debian
sudo apt update
sudo apt install -y python3 python3-venv python3-pip nodejs npm git sqlite3

# 若系统自带版本过低，用官方源安装 Python 3.14 与 Node 20
# Python 3.14: https://www.python.org/downloads/
# Node 20:     curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash - && sudo apt install -y nodejs
```

### 3.2 克隆仓库

```bash
git clone https://github.com/Pixel-fish-123/competition_web.git
cd competition_web
```

### 3.3 构建前端

```bash
cd frontend
npm install
npm run build        # 产物输出到 frontend/dist
cd ..
```

### 3.4 配置后端虚拟环境

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cd ..
```

### 3.5 初始化种子数据（可选）

```bash
cd backend
.venv/bin/python seed.py
cd ..
```

> 生产环境建议**不执行** seed.py，或执行后立即修改默认密码（见 0.3）。

### 3.6 创建 systemd 服务

创建 `/etc/systemd/system/competition-web.service`：

```ini
[Unit]
Description=Competition Web (FastAPI + Vue)
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/competition_web/backend
Environment=SECRET_KEY=你的随机密钥
Environment=PYTHONUNBUFFERED=1
# 可选：指定数据库路径
# Environment=DATABASE_URL=sqlite:///./competition.db
ExecStart=/opt/competition_web/backend/.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000
Restart=always
RestartSec=3
User=www-data

[Install]
WantedBy=multi-user.target
```

> 把 `/opt/competition_web` 替换为你的实际仓库路径。

启动并设置开机自启：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now competition-web
sudo systemctl status competition-web
```

### 3.7 验证

```bash
curl -s http://127.0.0.1:8000/ | head
```

## 4. Caddy HTTPS 反向代理

> 无论方案 A 还是 B，都建议用 Caddy 提供 HTTPS。**不使用 nginx**。

### 4.1 安装 Caddy

```bash
sudo apt install -y debian-keyring debian-archive-keyring apt-transport-https curl
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | sudo gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | sudo tee /etc/apt/sources.list.d/caddy-stable.list
sudo apt update
sudo apt install caddy
```

### 4.2 配置 Caddyfile

编辑 `/etc/caddy/Caddyfile`，参考 `deploy/Caddyfile`：

```
your-domain.com {
    email admin@your-domain.com
    reverse_proxy app:8000
}
```

- **方案 A（Docker）**：`app:8000` 指向 compose 网络内的服务名。
- **方案 B（systemd）**：改为 `127.0.0.1:8000`。

Caddy 自动申请并续期 Let's Encrypt 证书，自动处理 HTTP→HTTPS 跳转，并自动升级 WebSocket（`/ws/*` 对局实时推送无需额外配置）。

### 4.3 重启 Caddy

```bash
sudo systemctl restart caddy
sudo systemctl status caddy
```

### 4.4 验证 HTTPS

浏览器访问 `https://your-domain.com`，应看到锁图标（证书有效）且页面正常加载。

## 5. SQLite 备份与恢复

### 5.1 WAL 模式说明

数据库使用 SQLite **WAL 模式**，运行时会生成 `competition.db-wal` 与 `competition.db-shm` 伴生文件。**手动拷贝数据库文件时，必须连同 `-wal` / `-shm` 一起拷**，否则可能丢失最近未 checkpoint 的数据。

推荐使用 `sqlite3 .backup` 命令（`deploy/backup.sh` 已封装），它会正确处理 WAL，无需停服。

### 5.2 手动备份

```bash
# 在线安全备份（推荐）
sqlite3 /path/to/competition.db ".backup '/path/to/backup.db'"

# 或手动拷贝（必须连伴生文件一起）
cp competition.db competition.db-wal competition.db-shm /backup/dir/
```

### 5.3 使用备份脚本（推荐）

```bash
cd deploy
chmod +x backup.sh backup_restore_test.sh

# 手动备份
./backup.sh

# 备份到指定目录
./backup.sh /path/to/competition.db /path/to/backups
```

脚本特性：
- 使用 `sqlite3 .backup` 在线安全备份（WAL 正确）。
- 无 sqlite3 CLI 时自动回退 Python 备份。
- 备份文件写入 `./backups/`，文件名 `competition_YYYYMMDD_HHMMSS.db`。
- 仅保留最近 7 份，更早的自动删除。
- 成功退出码 0，失败退出码非 0。

### 5.4 恢复演练（重要）

**备份必须可恢复才算合格**。定期运行恢复演练脚本，它会从备份恢复到临时目录并校验各表行数与源库一致：

```bash
cd deploy
./backup_restore_test.sh
```

任一环节失败（恢复失败 / 行数不一致）则退出码非 0，说明备份不可用，需排查。

### 5.5 恢复流程（灾难恢复）

```bash
# 1. 停止服务（避免写入冲突）
sudo systemctl stop competition-web        # 方案 B
# 或 docker compose stop app               # 方案 A

# 2. 备份当前损坏库（可选）
mv competition.db competition.db.corrupt

# 3. 从备份恢复
sqlite3 competition.db ".restore '/path/to/backup.db'"

# 4. 重启服务
sudo systemctl start competition-web
```

### 5.6 配置 cron 定时备份

```bash
crontab -e
```

添加（每天凌晨 3 点备份，日志写入文件）：

```
0 3 * * * /opt/competition_web/deploy/backup.sh >> /var/log/competition-backup.log 2>&1
```

每周日跑一次恢复演练：

```
0 4 * * 0 /opt/competition_web/deploy/backup_restore_test.sh >> /var/log/competition-restore-test.log 2>&1
```

## 6. 常见问题

| 问题 | 处理 |
| --- | --- |
| 大陆节点域名无法访问 | 未完成 ICP 备案，云厂商拦截 80/443；改用香港节点或完成备案 |
| 首页 404 | 前端产物未构建或未放到 `frontend/dist`；重新 `npm run build` |
| 数据库被占用 | 备份/重置前先停止服务；WAL 模式下删除文件需先停 uvicorn |
| 忘记 SECRET_KEY | 重新生成并更新配置后重启服务（会失效所有已签发 JWT，需重新登录） |
| 端口被占用 | 修改 uvicorn `--port` 与 Caddy `reverse_proxy` 目标端口一致 |
