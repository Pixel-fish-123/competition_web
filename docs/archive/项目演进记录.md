## 一、项目概述与定位

萌新杯音游比赛网站，面向音游（Cytus2 等）社区比赛运营平台。单场比赛支持 ≤50 人（约 16~20 支 3 人队伍），覆盖宣传展示、报名、赛制编排、实时对局、积分排名全流程。核心特色是玩法模板插件系统，第一个模板为 demo「三角占领」赛时控制器。部署形态为单体单进程，一个端口跑通全站。

## 二、核心设计决策（评审修正）

原始需求整体成立，但评审发现 6 处需要修正或明确，否则会埋坑。这些决策在后续执行中全部落地，是项目的承重墙。

1. **参赛单位模型统一**：需求 2 与 4 语义重叠，统一引入 Participant（参赛单位）概念。个人参赛时参赛单位 = 单个选手；组队参赛时参赛单位 = 队伍（≤3 人）。比赛配置 `participant_type`：`team` / `individual` / `mixed`（混合，个人视作 1 人队伍）。赛制引擎、排名、积分全部只跟参赛单位打交道，一套代码同时支撑两种参与方式。

2. **赛制定义明确**：「小组轮换制」不是标准术语，明确为三种赛制：分组循环赛（Round Robin）、瑞士轮（Swiss）、单败淘汰（Single Elimination）。每场比赛创建时选定一种，统一实现 `TournamentEngine` 接口。

3. **出线规则移除**：不做「出线第二阶段」等多阶段赛制，单场单一赛制（Metis S6 从 scope 移除）。

4. **裁判指派**：比赛可配置 `referee_ids` 裁判组（Metis E3 修正）。对局操作仅 referee/admin 可操作棋盘，选手只读观看（用户 2026-08-02 最终确认，覆盖早前 Metis C1 修正）。

5. **人数上限**：比赛可配 `max_participants` 默认 50，满员拒绝报名（Metis E5 修正）。

6. **积分归属**：队伍获奖时每名成员各得该名次全额积分（不拆分），reason 注明「比赛名次·队伍<队名>」；全局榜按用户聚合（Metis C6/E15 修正）。

## 三、技术栈与架构

| 层 | 选型 |
|---|---|
| 后端 | Python 3.14（备选 3.12）+ FastAPI + Uvicorn |
| 数据库 | SQLite（WAL 模式），SQLAlchemy 2.0 + Pydantic v2 |
| 认证 | JWT（httpOnly Cookie + SameSite=Lax + Origin 校验防 CSRF）+ bcrypt |
| 限流 | slowapi（登录爆破 + 全局限流） |
| 实时 | FastAPI 原生 WebSocket（进程内连接管理器） |
| 前端 | Vue 3 + Vite + TypeScript + Pinia + Vue Router + Element Plus + axios |
| 测试 | pytest + httpx（内存 SQLite）；前端 vue-tsc + vite build |
| 部署 | Docker Compose（单容器）+ Caddy（HTTPS 反代）｜ 备选 systemd 裸跑 |

前端开发模式用 Vite Dev Server + 代理；生产模式构建产物由 FastAPI 静态托管（`frontend/dist`），单端口全站。

**依赖流向（后端）**：`api/* → core/* + models + schemas → services/* → tournaments/* + plugins/registry → core/ws_manager`。
**前端**：`views/* → api/http → Vite proxy(:8000)`；MatchPlay → `new WebSocket(/ws/...)`。

**目录结构**（monorepo 单仓）：

### 5.1 对局链路连环 bug 修复（fixed todos 1-6）

「对局玩法操作跑不通」被定位为一串连环 bug，不止一处，必须一起修链路才通。

- **todo 1 数据库重置脚本**：新增 `backend/reset_db.py`，可复用的一键重置脚本（完全重置、无备份、CLI 带确认/`--yes` 跳过）。关键点：文件顶部必须 import 全部 ORM 模型，否则 `drop_all` 只清 seed 已 import 的 5 张表，导致「完全重置」静默失效；锁检测必须前置，用 try/except PermissionError 包裹删除，捕获到占用时打印友好提示并退出（WAL 模式下 PRAGMA 检测不到其他进程占用，真正的检测点是删除时的文件锁）。

- **todo 2 对局操作核心链路**：前端 MatchPlay.vue 四处修复。①loadMatch 解包：`GET /api/matches/{mid}` 返回嵌套 `MatchDetailOut={match, session}`，原代码把整个包裹对象当扁平数据用，导致 participant_a/status/id 全 undefined，改为 `match.value = data.match`。②WS state 解包：WS 帧 state 是 get_state 的嵌套视图 `{controller_state: {...}, elapsed_minutes, sides, ...}`，而 TriangleState 期望扁平字段，解包为 `{...raw.controller_state, ...raw}`。③participant_id 推导：删除硬编码 `participant_id: 0`，新增 actingSide 切换（替哪一方操作），发送时按 defender/attacker 映射到 participant_a/b，null 时提示「该侧参赛者未确定，请先开赛」。④session_ended 保留状态：不再清空 state，保证「记录结果」按钮可见。⑤WS 重连终止守卫：组件卸载或 close.code===1008（对局被删除）时停止无限重连。后端 end_session 广播 session_ended 时附带最终公开视图（必须在 plugin.end_session 之前捕获活控制器）。

## 六、关键设计模式与约定

- **插件契约**：每个模板是一个目录，含 `plugin.py` + `manifest.json` + 前端组件，放进 `backend/app/plugins/<name>/` 即自动注册。继承 `GameplayPlugin`，manifest 非空 name/version，暴露 `plugin` 实例，不持全局状态。`validate_result` 只做值域/顺序/频率校验，不做分数真实性核验（Metis E7）。

- **引擎确定性恢复**：开赛/记分按「已批准报名 + 已完结对局」重建引擎并回放结果（单败淘汰后续轮次靠它解析参赛者）。参赛单位 id 升序保证引擎重建确定性。

- **报名状态机**：`pending → approved/rejected`（admin 审批端点）；赛程只认 approved。

- **WS 广播**：同步线程 put_nowait 入队 → 事件循环发送任务出队；满队列断开慢消费者。Cookie 鉴权 + 订阅白名单（参赛双方 / 裁判 / admin）+ 每连接 ≤10 msg/s 频率限制。

- **积分幂等结算**：防重复发放；队伍获奖成员各得全额。

- **比赛状态机**：`draft → registration → ongoing → finished`（cancelled 特殊）；进 ongoing 自动排表。

- **一键启动**：start.ps1（建 venv/装依赖/seed/双窗口/开浏览器）。

- **编号引用体系**：注释标注 `todo N`（功能归属）与 `Metis C/E/V{n}`（需求/验收约束），改动时保持引用可追溯。

## 七、反模式与禁忌

- **Metis E13**：ws_manager 只做连接登记与推送，禁止在其中做任何鉴权。
- **Metis E7**：插件 create_session 只做值域校验，禁止校验「得分真实性」。
- **前端禁止 `as any` / `@ts-ignore`**：类型错误必须真修（fixed todo 13 已清理全部 as any）。
- **`plugins/routes.py` 内存 `_sessions` 是临时反模式**（重启丢失）；会话读写应走 GameSession DB（DB 桥已实现，_sessions 仅作缓存）。
- **`points_service` 复用 `match_service` 的私有 `_` 助手**（`_approved_participant_ids` 等），重构勿破坏其签名。

## 八、部署与运维

- **目标环境**：国内轻量服务器（腾讯云/阿里云香港 2C2G 优先，免备案），观众主要在国内，不使用 Cloudflare Pages（2026-08-02 决策）。
- **方案 A：Docker Compose（推荐）**：单容器构建镜像 → 启动 uvicorn → 数据卷挂载 SQLite；Caddy 反代提供 HTTPS（自动申请证书）。
- **方案 B：裸进程 + systemd（无 Docker 备选）**：Python 3.12 + Node 构建前端 → systemd 管理 uvicorn → Nginx/Caddy 反代 HTTPS。
- **备份恢复**：cron 每天 `backup.sh`（sqlite3 .backup + 保留最近 7 份）；`backup_restore_test.sh` 做恢复演练（备份必须可恢复才合格）；SQLite WAL 备份需连同 -wal/-shm 一起拷。
- **上线清单**：域名 + HTTPS（国内服务器注意 ICP 备案）、健康检查 `/api/health`、日志轮转、密钥管理（JWT_SECRET / 管理员初始密码经环境变量注入，不入库不入 git）、服务器防火墙仅开放 80/443、数据库定期 VACUUM。
