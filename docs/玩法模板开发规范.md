# 玩法模板开发规范

> 本文档定义「萌新杯音游比赛平台」玩法插件（GameplayPlugin）的完整契约与开发流程。
> 后端契约见 `backend/app/plugins/base.py`，注册机制见 `backend/app/plugins/registry.py`。
> 内置示例：`backend/app/plugins/triangle_occupy/`（demo「三角占领」）。

---

## 1. 插件是什么

玩法插件把「一局对局的玩法逻辑」从平台核心中解耦出来。平台负责对局生命周期（建会话、广播、持久化、权限），插件负责「这个玩法怎么玩」。

每个插件是一个独立目录，包含 `manifest.json` 与 `plugin.py`。应用启动时（lifespan）自动扫描、注册并挂载 `/api/gameplay/<name>/*` 路由。

---

## 2. 目录结构

```
backend/app/plugins/
├── base.py                 # GameplayPlugin 抽象基类（契约）
├── registry.py             # 插件注册表 + 自动发现
├── routes.py               # 路由挂载（/api/gameplay/<name>/*）
└── <your_plugin>/          # 你的插件目录
    ├── manifest.json       # 插件元数据（必填）
    ├── plugin.py           # 插件实现（必填）
    └── ...                 # 其他资源（规则、配置、控制器等）
```

---

## 3. manifest.json（必填字段）

`manifest.json` 位于插件目录根，**`name` 与 `version` 必须非空**，否则注册时抛 `ValueError`。

```json
{
  "name": "my_plugin",
  "version": "1.0.0"
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `name` | 是 | 插件唯一名称，也是注册表键与路由前缀的一部分（`/api/gameplay/<name>/*`） |
| `version` | 是 | 语义化版本号，如 `"1.0.0"` |

> 无 `manifest.json` 的目录会被静默跳过，不会报错。

---

## 4. plugin.py（必暴露 `plugin` 实例）

`plugin.py` 必须：

1. 继承 `GameplayPlugin` 并实现全部 5 个抽象方法。
2. 在文件末尾暴露模块级实例 `plugin = MyPlugin()`。
3. 类属性 `name` / `version` 与 `manifest.json` 一致（不一致会抛 `ValueError`）。

```python
from app.plugins.base import GameplayPlugin


class MyPlugin(GameplayPlugin):
    name = "my_plugin"
    version = "1.0.0"

    def create_session(self, match_id: int, config: dict) -> dict:
        ...

    def get_state(self, session_id: int, state: dict) -> dict:
        ...

    def submit_result(self, session_id: int, state: dict, participant_id: int, payload: dict) -> dict:
        ...

    def validate_result(self, session_id: int, state: dict, participant_id: int, payload: dict) -> bool:
        ...

    def end_session(self, session_id: int, state: dict) -> dict:
        ...


plugin = MyPlugin()
```

## 5. 五个抽象方法契约

所有方法收到的是**服务端持久化的对局状态 `state`（dict）**，方法返回新状态，由路由层负责存储。**方法自身不得修改传入的 `state`**（应返回新 dict）。

非法输入统一抛 `ValueError`，路由层会将其转换为 HTTP 400。

### 5.1 `create_session(match_id, config) -> dict`

创建一局对局会话，返回初始状态 dict。

| 参数 | 说明 |
| --- | --- |
| `match_id` | 比赛对局 id（由比赛/对局模型分配） |
| `config` | 玩法配置（歌曲库、时长、难度等），由比赛配置传入 |

- 返回：初始会话状态 dict（后续透传给 `get_state` / `submit_result` 等）。
- 异常：`ValueError`（配置缺失或非法，如缺少必须字段、值越界）。

### 5.2 `get_state(session_id, state) -> dict`

返回当前会话状态，用于广播 / 客户端轮询。

- 默认可原样返回存储的 `state`。
- 需要时（如把内部字段裁剪为客户端可见的公开视图）可在此加工。
- **不得修改传入的 `state`**。

### 5.3 `submit_result(session_id, state, participant_id, payload) -> dict`

应用一次玩家 / 裁判操作，返回更新后的状态 dict。

| 参数 | 说明 |
| --- | --- |
| `participant_id` | 操作者（选手或裁判）用户 id |
| `payload` | 操作内容（如落子坐标、得分提交） |

- 返回：更新后的会话状态 dict。
- 异常：`ValueError`（操作非法，如非本局参与者、状态机不允许等）。

### 5.4 `validate_result(session_id, state, participant_id, payload) -> bool`

操作合法性校验：身份 / 时间窗 / 频率 / 值域。

> **Metis E7（重要）**：`validate_result` **只做值域等结构性校验**，**禁止校验「得分真实性」**（得分是否与谱面 / 规则一致不属于本层职责）。得分真实性由上层业务或人工判定。

### 5.5 `end_session(session_id, state) -> dict`

结束对局，返回最终结果 dict。

返回 dict **必须包含以下键**：

| 键 | 说明 |
| --- | --- |
| `winner` | 胜者 participant_id，或 `None` |
| `is_draw` | 是否平局（bool） |
| `score_a` | 方 A 得分 |
| `score_b` | 方 B 得分 |

## 6. 约束与反模式

### 6.1 插件不得持全局状态

插件是进程内单例，**不得持有跨对局的可变全局状态**（契约约束）。

- 活控制器实例（如 `triangle_occupy` 的 `_CONTROLLERS`）仅内存持有，重启后靠从序列化 `state` 重建（`_restore_controller`）。
- 对局状态本身由路由层持久化到 `GameSession` DB，不依赖插件内存。

### 6.2 JSON 往返键类型

对局状态经 JSON 序列化 / 反序列化后，dict 的 int 键会变成字符串。`sides` / `cells` 等 int 键需规范化，否则 `validate_result` 匹配失败。

### 6.3 歌曲库数量

若玩法依赖歌曲库（如 `triangle_occupy`），歌曲不足会抛 `ValueError`（如「歌曲库至少需要 23 首」），经路由转 400。

---

## 7. 前端组件命名约定

前端组件放在 `frontend/src/plugins/<name>/`，与后端插件目录**对称命名**。

```
frontend/src/plugins/
└── <name>/
    ├── index.ts            # 导出组件（TriangleBoard / TriangleControls 等）
    ├── TriangleBoard.vue   # 棋盘 / 玩法主视图
    └── TriangleControls.vue# 裁判操作控件（可选）
```

> 当前 `MatchPlay.vue` 通过插件名映射表解析组件（`PLUGIN_COMPONENTS`）。新增玩法需在映射表中登记 `name → { board, controls }`。

---

## 8. 如何新增一个玩法插件

1. **创建目录**：在 `backend/app/plugins/` 下建子目录 `my_plugin/`。
2. **写 manifest**：创建 `manifest.json`，`name` / `version` 非空。
3. **写 plugin.py**：继承 `GameplayPlugin` 实现 5 个抽象方法，末尾暴露 `plugin = MyPlugin()`。
4. **只做值域校验**：`validate_result` 只做结构性校验（Metis E7），不校验得分真实性；非法输入抛 `ValueError`。
5. **重启应用**：lifespan 自动 discover + register + mount 路由，无需改其他代码。
6. **写前端组件**：在 `frontend/src/plugins/<name>/` 放对应组件，并在 `MatchPlay.vue` 的 `PLUGIN_COMPONENTS` 映射表中登记。
